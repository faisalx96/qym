SDK guide

SDK structure & exports

Everything you use day to day lives at the top level of the qym package: one evaluator class, four dataset loaders, the observer types, and the group-analysis helpers. This page is the map — what each export is, what you import it for, and the run-method behavior that trips people up.

The one mental model

qym evaluates one task over one dataset and scores every output with one or more metrics. Everything else is configuration around that loop:

dataset item  ->  task function  ->  output  ->  metric(s)  ->  EvaluationResult
                                              ->  local artifacts (qym_results/)
                                              ->  optional platform stream
                                              ->  optional local progress events

The entry point is always Evaluator. There is no free-standing evaluate() or run() function — you construct an Evaluator and call a method on it.

from qym import Evaluator, CsvDataset

def task(question):
    return my_model(question)

result = Evaluator(
    task=task,
    dataset=CsvDataset("qa.csv"),
    metrics=["exact_match"],
).run(show_tui=False)

print(result.success_rate)

Top-level exports

These are the names exported from the qym package (its __all__). Import everything you need directly from qym — you should rarely need to reach into submodules.

ExportKindWhat it's for
EvaluatorclassThe entry point. Holds the task, dataset, metrics, and config; runs the loop via .run() / .arun() / .run_parallel().
EvaluationResultclassThe object a run returns. Holds aggregate stats, per-item results, errors, run metadata, and saved-artifact paths.
CsvDatasetclassLoad items from a local .csv file with configurable column mapping.
JsonlDatasetclassLoad items from a local .jsonl file (one JSON object per line, fixed keys).
InMemoryDatasetclassWrap a list of dicts you build in code — handy for generated or programmatic evals.
QymDatasetclassLoad a versioned dataset from the qym platform by name (uses QYM_BASE_URL / QYM_API_KEY).
EvaluationObserverclassBase class for named lifecycle hooks (on_run_start, on_item_complete, …) when embedding qym in a service.
ProgressCallbackObserverclassAdapts a single ProgressSnapshot callback to the observer interface; used internally by progress_callback.
ProgressSnapshotclassThe immutable progress event your progress_callback receives.
MultiModelRunnerclassThe engine behind multi-model and multi-run execution; run_parallel() delegates to it.
RunSpecclassA structured description of one run for run_parallel() (an alternative to a plain dict).
GroupRunAnalysisclassThe result object returned by group-analysis helpers.
analyze_group_runsfunctionCompute Pass@K, Avg@K, consistency, reliability, and more over a set of results.
compare_group_runsfunctionCompare two sets of results with strict cohort semantics.
list_available_metricsfunctionReturn the names of every registered metric (built-ins plus anything you registered).
builtin_metricsfunctionReturn the built-in metric registry as a mapping of name to callable.

Verify your install in one line. from qym import Evaluator, CsvDataset should import cleanly. To list the metric names available in your environment, run from qym import list_available_metrics; print(list_available_metrics()).

The Evaluator constructor

The constructor takes the three required pieces plus optional configuration. Signature:

Evaluator(
    task,                    # callable or supported framework object
    dataset,                 # dataset object, or a string (resolved — see below)
    metrics,                 # list of metric names and/or callables
    config=None,             # dict or EvaluatorConfig
    observer=None,           # EvaluationObserver
    model=None,              # str or Sequence[str]
    langfuse_client=None,    # deprecated and ignored
    progress_callback=None,  # Callable[[ProgressSnapshot], None]
    input_mapping=None,      # map dataset input names to task parameter names
)
ArgumentRequiredTypeNotes
taskYescallable / objectCalled once per dataset item with that item's input.
datasetYesobject or strA dataset object (CsvDataset, etc.) or a string that qym resolves (see String datasets below).
metricsYeslist[str | Callable]Built-in metric names and/or your own callables.
configNodict or EvaluatorConfigA dict is converted into an EvaluatorConfig for you. See Configs & options.
observerNoEvaluationObserverLower-level lifecycle hooks for service integrations.
modelNostr or Sequence[str]A single model label, or a list to run the same task across multiple models.
langfuse_clientNo—Deprecated and ignored. qym uses platform / OpenTelemetry tracing; passing this only logs a warning.
progress_callbackNoCallableReceives a ProgressSnapshot on each lifecycle event. A shortcut on the constructor only — not on run_parallel().
input_mappingNodict[str, str]Maps dataset input names to task parameter names before the task is called. Most useful with CsvDataset(input_col=[...]), e.g. {"sql_prompt": "question"}.

Langfuse is not part of the runtime. There is no Langfuse dataset source and no langfuse_* config. The langfuse_client argument exists only for backward compatibility and does nothing.

Run methods: run() vs arun() vs run_parallel()

Once you have an Evaluator, there are three ways to execute it. They share the same loop but differ in calling context, defaults, and return shape.

MethodCall fromReturnsauto_save default
.run(...)normal (sync) codeone EvaluationResult, or a list for multi-model runsTrue
await .arun(...)inside an async callerone EvaluationResultFalse
Evaluator.run_parallel(runs, ...)normal (sync) code; static methodlist[EvaluationResult]False

The auto_save mismatch. run() saves artifacts by default (auto_save=True); arun() does not (auto_save=False). If you switch to the async path, pass auto_save=True explicitly or call result.save(...) yourself.

run()

The everyday entry point. It handles event-loop setup for you (including Jupyter) and runs the async core synchronously.

def run(
    show_tui=True,
    auto_save=True,
    save_format="csv",       # "csv", "json", or "xlsx"
    max_parallel_runs=None,  # only used for multi-model runs
): ...
  • Single model → returns one EvaluationResult.
  • Multiple models (model=[...]) → returns a list[EvaluationResult], one per model. Guard your code with isinstance(result, list) when a run might be multi-model.
  • max_parallel_runs only applies to multi-model runs: None runs all models in parallel, 1 runs them sequentially, N runs N at a time.

run() prints nothing by default. The end-of-run summary is silent unless you set the environment variable QYM_SHOW_SUMMARY=1. To read results in code, use the EvaluationResult object (e.g. result.success_rate) regardless of that setting.

arun()

Use this when your caller is already inside an event loop and should await the evaluation. It returns a single EvaluationResult and, as noted above, defaults auto_save=False.

result = await Evaluator(
    task=my_async_task,
    dataset=dataset,
    metrics=["exact_match"],
).arun(show_tui=False, auto_save=True)

run_parallel()

A static method for running several different configurations at once — different tasks, datasets, metrics, or config per run. Each entry is a dict (or RunSpec); the runs argument is the first parameter.

from qym import Evaluator

results = Evaluator.run_parallel(
    runs=[
        {"name": "baseline",  "task": baseline_task,  "dataset": dataset, "metrics": ["exact_match"]},
        {"name": "candidate", "task": candidate_task, "dataset": dataset, "metrics": ["exact_match"]},
    ],
    show_tui=False,
    max_parallel_runs=2,
)

progress_callback is not available here — pass observer=ProgressCallbackObserver(on_progress) instead. For the difference between multi-model (model=[...]) and multi-run (run_parallel), and the analysis helpers, see Multi-model & group analysis.

The four dataset classes

All four implement the same item contract — every item resolves to id, input, expected_output, and metadata — but they differ in source and constructor.

CsvDataset

Local .csv with configurable columns. Pass input_col=[...] for multi-column dict inputs. Cells that start with { or [ are parsed as JSON; everything else stays a string.

JsonlDataset

Local .jsonl, one JSON object per line. Keys are fixed (input, optional expected_output, metadata, id/item_id) — no column remapping.

InMemoryDataset

Wrap a Python list of dicts. Ideal for generated cases or quick programmatic evals with no file on disk.

QymDataset

A versioned dataset stored on the qym platform, fetched by name over QYM_BASE_URL with QYM_API_KEY.

from qym import CsvDataset, JsonlDataset, InMemoryDataset, QymDataset

# Local CSV with column mapping
csv_ds = CsvDataset(
    "datasets/qa.csv",
    input_col="question",
    expected_col="answer",
    id_col="id",
    metadata_cols=["domain", "difficulty"],
)

# Local CSV with multiple task inputs and cleaner task parameter names
text2sql_ds = CsvDataset(
    "datasets/text2sql.csv",
    input_col=["sql_prompt", "sql_context"],
    expected_col="sql",
)
Evaluator(
    task=text2sql_task,
    dataset=text2sql_ds,
    metrics=[valid_sql],
    input_mapping={"sql_prompt": "question", "sql_context": "schema"},
)

# Local JSONL (fixed keys, no remapping)
jsonl_ds = JsonlDataset("datasets/qa.jsonl")

# Built in code
mem_ds = InMemoryDataset([
    {"input": "2 + 2", "expected_output": "4", "metadata": {"topic": "math"}},
])

# Platform dataset by name (optionally pin a version or alias)
plat_ds = QymDataset("support-regression", alias="production")

See Datasets in depth for column rules, the JSON-in-cell behavior, and platform versioning.

String datasets & how they resolve

You can pass a plain string as dataset instead of a dataset object. qym resolves it like this:

  • If the string is an existing local .csv file → loaded as a CsvDataset.
  • If it's an existing local .jsonl file → loaded as a JsonlDataset.
  • If it's an existing local file with any other extension → an error (unsupported extension).
  • Otherwise (the path does not exist) → treated as a qym platform dataset name and fetched as a QymDataset.

A typo'd file path becomes a platform lookup. Because any non-existent path falls through to the platform, a mistyped local path like "datsets/qa.csv" is treated as a platform dataset name. Without QYM_BASE_URL / QYM_API_KEY that surfaces as a DatasetNotFoundError, not a "file not found." When in doubt, construct the dataset object explicitly (e.g. CsvDataset("datasets/qa.csv")) so a missing file fails loudly and locally.

The task-output envelope

A task returns the value to score. Returning a plain value (string, number, list, etc.) is the common case. A dict return is special — qym reserves it for an explicit output envelope, and it must match exactly:

def rag_task(question):
    docs = retrieve(question)
    answer = call_llm(question, context=docs)
    return {"output": answer, "metadata": {"retrieved_context": docs}}
  • The dict must have exactly the keys output and metadata — no more, no fewer.
  • metadata must itself be a dict.
  • Only output is shown as the visible task output; built-in metrics score against it.
  • Anything else (missing keys, extra keys, or a non-dict metadata) raises InvalidTaskOutputError.

The exact error message, copied from the source, is:

Task returned a dict. Dict task outputs must use qym's envelope {"output": <visible output>, "metadata": <dict>} (missing keys: ...; unexpected keys: ...).

If you want to return structured data as the output itself, return a non-dict (e.g. a list) or wrap it in the envelope. See Custom metrics for how a metric reads output["metadata"] from the envelope.

Where things live (import paths)

Prefer the top-level qym imports — they are the stable, supported surface. A few things you may reach for live in submodules:

SymbolImport from
All public exports listed aboveqym
EvaluatorConfigqym.core.config
InvalidTaskOutputErrorqym.core.evaluator
DatasetNotFoundError, CsvDatasetSchemaErrorqym.utils.errors

Exceptions are not all in one place. InvalidTaskOutputError is defined in the evaluator module, while dataset errors live in qym.utils.errors. If you catch qym exceptions, import each from its actual module rather than assuming a single errors namespace.
