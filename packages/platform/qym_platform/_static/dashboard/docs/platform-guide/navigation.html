PLATFORM GUIDE

Navigation & roles

The platform is organized around projects. Pick a project first; its dashboard, runs, datasets, reviews, and settings then stay inside that project boundary.

Find your way around

DestinationUse it for
ProjectsOpen an accessible project or create one when your role permits it.
DashboardRead the project's evaluation summary and recent activity.
ChartsTrack metric and latency trends by task, dataset, version, run, and model.
RunsFilter, inspect, compare, submit, approve, or delete evaluation runs.
ModelsCompare model-level quality, reliability, latency, retries, and trace statistics.
ReviewsCurate root-cause corrections used by AI-assisted analysis.
DatasetsVersion test data, publish releases, assign aliases, and trace item history.
Project SettingsManage project details, members, keys, LLM connections, and project lifecycle.
DocsRead SDK, platform, CLI, and API guidance without leaving the app.

Use the project switcher in the shell to move between projects. Filters, URLs, runs, datasets, keys, and review records remain project-scoped.

Roles at a glance

RoleWhat it adds
Project memberCan use the project's dashboards, runs, datasets, reviews, API keys, and LLM connections. Members may modify review data and create keys; a key creator may revoke their own key.
Project managerAdds member and role management, run approval decisions, broader run deletion, key revocation, and project lifecycle controls.
Platform adminCan access every project, manage platform users and projects, and view or restore deleted runs.

Project role and platform role are separate. A platform MEMBER can be a project MANAGER. A platform ADMIN has manager-equivalent access everywhere.

Run ownership and approval

  • A run owner can submit a completed, failed, or rejected run and can delete their own run. Submitting asks for confirmation and takes an optional comment.
  • A project manager or platform admin can also submit any run of the project on behalf of its owner (the review history says so), transfer a run to another project member, approve or reject a submitted run, reverse that decision, and delete project runs.
  • While a run is submitted or approved its scores are locked: they cannot be edited or reset, and its passes cannot be deleted. A manager rejects or unapproves the run to reopen them. Deleting passes needs the same rights as deleting the run.
  • Deletion is recoverable for a limited time: runs move to Deleted Runs, where platform admins can restore them until retention permanently removes them (30 days after deletion by default). Only platform admins can view that area.
