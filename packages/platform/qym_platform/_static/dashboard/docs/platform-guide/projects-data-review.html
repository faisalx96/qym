PLATFORM GUIDE

Projects, data & review

Projects are the platform's access and data boundary. Their settings connect people and automation; datasets define the evidence; reviews turn analysis into reusable corrections.

Projects

The Projects page lists projects you can access, with your role and activity summary. Platform admins can create projects. A project manager can also create another project; its creator becomes its first manager.

Project Settings contains five areas:

TabPurpose
GeneralName, slug, description, current role, member count, and status.
MembersAdd people and assign MEMBER or MANAGER. Only managers/admins can change membership, and the final manager cannot be removed or demoted. Removing a member revokes their API keys for the project.
API KeysCreate project-bound Bearer keys, identify them by name/prefix, and revoke eligible keys.
LLM ConnectionsAdd, edit, test, choose a default, or remove providers used by AI-assisted root-cause analysis.
Danger ZoneAdmins can archive the project (reversible) or delete it permanently.

Archive hides; Delete removes. Archiving hides the project from navigation and stops its API keys, but deletes nothing; an admin can unarchive it from Admin → Projects. Deleting is permanent and removes the project's datasets, API keys, members, LLM connections and analysis settings after you type the project name. A project that still has runs, including runs in Trash, cannot be deleted: its runs must be deleted and then purged from Trash after the deleted-run grace period. Until then, archive it.

API keys

Any project member may create a key. The raw token is shown once; save it immediately. Later lists show only metadata and the first eight-character prefix. A key is fixed to one project, so use a different key for every project and environment.

QYM_BASE_URL=https://qym.example.com
QYM_API_KEY=<token-shown-once>

A key's creator, a project manager, or a platform admin may revoke it. Stored scope labels are informational today and are not enforced; project membership is the security boundary.

LLM connections

Project members can manage connections used by root-cause analysis. Give each connection a provider, model, endpoint where applicable, and secret key; test it before setting it as default. Secrets are encrypted at rest when the operator has configured the platform encryption key.

The analyzer uses the project's default connection, or the first available connection when no default is set. Approved corrections from Reviews provide reusable examples for later analysis.

Datasets

The dataset catalog is project-scoped. Import CSV or JSONL to create a dataset, then work through its version lifecycle:

  1. Create or clone a draft.
  2. Add, edit, bulk upsert, or remove items while it is a draft.
  3. Publish the nonempty version to make its content immutable.
  4. Assign an alias such as production to a published version.

Inside a dataset, use:

  • Items for search, labels, item editing, revision history, neighboring items, and each item's linked runs;
  • Runs for evaluations that used the dataset or selected version;
  • Lineage for version ancestry and change counts; and
  • Compare for item-level differences between two versions.

Downloads are JSONL. To change published content, create a new draft from that version rather than editing it in place.

Reviews and corrections

Reviews collects root-cause and solution corrections from manual work and AI analysis. Filter by status, source, project context, task, dataset, model, run, text, and other facets. Open a correction to inspect its revision and review history.

StatusMeaning
PendingWaiting for a human decision.
ApprovedAccepted and available as a few-shot example for future analysis.
RejectedRetained for audit, but excluded from analyzer examples.

You can edit a correction, approve or reject it with a comment, reset it to pending, or delete it. Select several corrections for bulk approve, reject, reset, or delete.

Deleted runs

Deleting a run is soft-delete: it leaves active views but keeps its data and deletion audit details. Deleted Runs is visible only to platform admins, who can restore a run to its project. Retention permanently removes a deleted run and all its results after a grace period (QYM_DELETED_RUN_GRACE_DAYS, 30 days by default); the page shows each run's purge date and flags runs with fewer than 3 days left.
