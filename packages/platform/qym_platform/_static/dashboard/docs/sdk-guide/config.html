SDK GUIDE

Configs & options

Every run is shaped by one object: EvaluatorConfig. This page is the complete, code-verified reference for its fields, the environment variables the SDK reads, how CLI flags map back into the same config, and the patterns worth copying for smoke tests, production jobs, and multi-run comparisons.

How configuration flows

There is a single configuration object — EvaluatorConfig — and every entry point funnels into it:

  • Python: pass an EvaluatorConfig instance, or a plain dict with the same keys. The constructor does EvaluatorConfig(**(config or {})), so a dict is validated by Pydantic exactly like the typed object.
  • CLI: qym run create forwards its flags into the same config. Anything without a dedicated flag can be set through --config (a JSON string merged into the config).
  • Environment: secrets and deployment endpoints (platform URL, API key, judge credentials, TLS) are read from environment variables, never hardcoded.

A rule of thumb: explicit Python config in services and notebooks, environment variables for secrets and per-deployment endpoints, CLI flags for shell automation.

from qym import Evaluator
from qym.core.config import EvaluatorConfig

config = EvaluatorConfig(
    run_name="support-rag-smoke",
    task_name="support-rag",
    max_concurrency=5,
    timeout=120,
    max_retries=1,
    run_metadata={"prompt_version": "2026-04-24-a"},
)

result = Evaluator(
    task=my_task,
    dataset=my_dataset,
    metrics=["exact_match"],
    config=config,
).run(show_tui=False)

The dict form is equivalent — useful when config comes from JSON, YAML, or a service request:

result = Evaluator(
    task=my_task,
    dataset=my_dataset,
    metrics=["exact_match"],
    config={
        "run_name": "support-rag-smoke",
        "task_name": "support-rag",
        "max_concurrency": 5,
        "timeout": 120,
        "max_retries": 1,
        "run_metadata": {"prompt_version": "2026-04-24-a"},
    },
).run(show_tui=False)

Validation happens at construction. Because the config is a Pydantic model, an unknown key or an out-of-range value (for example max_concurrency=0, which has a ge=1 constraint) raises immediately — before any dataset item runs.

Complete EvaluatorConfig reference

Every field below is defined on EvaluatorConfig in qym/core/config.py. Defaults are copied directly from the source. Fields are grouped by what they control.

Run identity

FieldTypeDefaultWhat it does
run_nameoptional strNoneHuman-readable run name used in artifacts and the platform.
task_nameoptional strNone (auto-derived)Stable task identity. Overrides the name auto-derived from the task callable so renames of files/functions do not split history.
run_metadatadict{}Non-secret tags attached to the run (job ID, prompt version, dataset version, owner, release).
git_branchoptional strNone (auto-detected)Override the auto-detected git branch.
git_commitoptional strNone (auto-detected)Override the auto-detected commit hash (useful in CI or detached HEAD).
cli_invocationoptional strNoneRecords the command used to launch the run. Set automatically by the CLI.

Keep secrets out of run_metadata. Its contents are written into artifacts and shown in the platform UI. Store labels, not credentials.

Execution

FieldTypeDefaultWhat it does
max_concurrencyint (≥1)10How many dataset items run at once. Lower it for provider rate limits; raise it once the run is stable.
max_metric_concurrencyint (≥1)1How many metrics evaluate concurrently per item. Raise it when metrics call external services.
timeoutoptional float (>0)300Wall-clock cap per task item, in seconds. Set None only when you trust the task never to hang.
metric_timeoutoptional float (>0)60.0Wall-clock cap for each metric attempt. A timeout is retried; after the final attempt it is recorded through the normal metric-error path as score 0 plus an error, so it is visible, is a scorer error, and counts as 0 in the run mean (on the platform and in the local summary), or is left out of it for a lower-is-better metric. Set None to disable the cap and timeout retries.
metric_max_retriesint (≥0)2Retries after a metric attempt reaches metric_timeout. The default allows three total attempts. This is separate from max_retries, which retries the task itself.
max_retriesint (≥0)2Retries on task failure. Use 0 for deterministic smoke tests and debugging.
samplesint (≥1)1Repeat runs: evaluate every item k times (k sequential passes) as ONE run and report Pass@k/Pass^k/Consistency/Reliability. See Repeat runs & pass@k.
report_koptional int (≥1)NonePublish Pass@k and Pass^k at a subset size no larger than samples, using unbiased estimates from all stored passes. Other repeat statistics still use the full pass pool.
interrupt_grace_secondsfloat2.0Grace window for cleanup and final-status emission when a run is interrupted.

Timeout budget is per attempt. With the defaults, one permanently hung metric can consume about three minutes before it is recorded as an error: 60s × (2 retries + 1). Tune metric_timeout and metric_max_retries together for your provider and CI budget.

Output, checkpointing & recovery

FieldTypeDefaultWhat it does
output_dirstr"qym_results"Base directory for saved artifacts and checkpoints.
checkpoint_enabledboolTrueEnables incremental checkpoint writes so an interrupted run can resume.
checkpoint_formatstr"csv"Checkpoint serialization format.
checkpoint_flush_each_itemboolTrueFlush after each item for stronger durability.
checkpoint_fsyncboolFalseForce a filesystem sync on each flush. Worth the small cost on high-value long runs.
resume_fromoptional strNonePath to a checkpoint CSV (or saved result) to resume from.
resume_rerun_errorsboolFalseOn resume, re-run rows that previously errored instead of preserving the failures.

Dataset selection

These two fields apply only when the dataset is resolved from the qym platform (a dataset name string rather than a local file or a dataset object). See Datasets for the full resolution rules.

FieldTypeDefaultWhat it does
dataset_versionoptional strNonePin a specific platform dataset version.
dataset_aliasoptional strNoneResolve by alias instead of version. When neither version nor alias is given, the platform dataset defaults to the production alias.

Model routing

FieldTypeDefaultWhat it does
modeloptional strNoneSingle model label passed to task signatures and stored in metadata.
modelsoptional list[str]NoneRun the same task/dataset/metrics across several models. A comma-separated string is normalized into a list.
model_fulloptional strNoneFull provider-prefixed model ID (e.g. qwen/qwen3.5-397b-a17b) for integrations that call the API directly.
force_model_overrideboolFalseReplace a hardcoded OpenAI chat-completion model at the SDK boundary. Use only when you understand the adapter behavior.

Prefer the constructor for models. Passing model="gpt-4o-mini" or model=["a", "b"] to Evaluator(...) sets config.model/config.models for you. A multi-model run returns a list of EvaluationResult — see Multi-model & group analysis.

Platform streaming

FieldTypeDefaultWhat it does
platform_urloptional strNone (falls back to QYM_BASE_URL)Base URL of the qym platform to stream the run to.
platform_api_keyoptional strNone (falls back to QYM_API_KEY)Project-scoped API key for ingestion. Prefer the environment variable for secrets.
platform_timeoutfloat (>0)5.0Per-request timeout for platform calls, in seconds.
live_modestr"platform"Streaming policy: platform (default), local (opt out of streaming), or auto.
ui_portint0Port for the local run UI; 0 chooses one automatically.

Don't hardcode platform_api_key in source. Set QYM_API_KEY in the environment and leave the field unset; the SDK falls back to the env var. API keys are project-scoped, shown once on creation, and sent as Authorization: Bearer <token>.

Tracing

FieldTypeDefaultWhat it does
otel_enabledboolTrueEnables OpenTelemetry auto-instrumentation when instrumentors are installed. A no-op if none are present.
phoenix_enabledboolFalseAdditionally export traces to Phoenix over OTLP.
phoenix_endpointoptional strNonePhoenix collector endpoint, e.g. http://localhost:6006/v1/traces.

There are no Langfuse config fields. Langfuse has been removed from the SDK runtime. The langfuse_client constructor argument is deprecated and ignored (it only logs a warning). Do not configure Langfuse keys, hosts, or dataset names — they are not read by anything.

Environment variables

These are the variables the SDK and CLI actually read. Each name and fallback below is taken from the source.

Platform connection

VariableRead byNotes
QYM_BASE_URLSDK, CLIPlatform base URL. Resolved by get_platform_url_env, which strips a trailing slash. When unset, the SDK falls back to http://localhost:8000.
QYM_API_KEYSDK, CLIProject-scoped API key for ingestion and authenticated platform commands. Sent as a Bearer token.
QYM_PLATFORM_DEBUGSDK platform clientEnable streaming debug logging. Set to 1 or a file path.
QYM_SHOW_SUMMARYSDK resultsOpt in to the printed run summary. Truthy values: 1, true, yes, on. When unset, run() prints nothing and print_summary() is a no-op.

QYM_BASE_URL is the canonical platform variable. Point it at your deployment, for example https://qym.example.com. The same variable doubles as the default platform URL for QymDataset name resolution.

TLS for self-signed / internal CAs

When the platform sits behind an internal certificate authority, these variables control how the SDK's platform HTTP client verifies HTTPS. The platform-specific variable wins; the unprefixed one is the fallback.

VariableFalls back toNotes
QYM_PLATFORM_CA_BUNDLEQYM_CA_BUNDLEPath to a custom CA bundle used for platform HTTPS calls.
QYM_PLATFORM_SSL_VERIFYQYM_SSL_VERIFYToggle certificate verification (default on). Accepted off values: 0, false, no, off, disable, disabled.

Prefer a CA bundle over disabling verification. Setting QYM_PLATFORM_SSL_VERIFY=0 turns off certificate checks entirely. Point QYM_PLATFORM_CA_BUNDLE at your internal CA instead whenever you can.

Judge metrics

LLM-as-judge metrics use the separately installed openai client and read their provider configuration from the environment. See LLM-as-judge for the full behavior.

VariableFalls back toNotes

QYM_JUDGE_API_KEYOPENAI_API_KEYProvider API key. validate() raises if neither is set.
QYM_JUDGE_BASE_URLOPENAI_BASE_URLBase URL for OpenAI-compatible providers (vLLM, Ollama, etc.).

Phoenix tracing

VariableNotes
PHOENIX_ENDPOINTPreferred Phoenix collector endpoint.
PHOENIX_COLLECTOR_ENDPOINTCompatibility alias for the endpoint.

A local .env is loaded automatically. On construction, Evaluator loads the .env in the current working directory (and only that one) before reading config or auto-detecting environment values.

Config patterns

Local, deterministic smoke test

Zero credentials, no retries, low concurrency — built for iterating on the task and metric contract.

config = {
    "run_name": "local-smoke",
    "task_name": "support-rag",
    "max_concurrency": 2,
    "timeout": 60,
    "max_retries": 0,
    "checkpoint_enabled": True,
    "run_metadata": {"suite": "smoke"},
}

Provider-backed production job

Higher concurrency, durable checkpoints, platform streaming via environment variables, and reproducibility metadata.

import os

config = {
    "run_name": "nightly-support-rag",
    "task_name": "support-rag",
    "max_concurrency": 8,
    "max_metric_concurrency": 2,
    "timeout": 300,
    "metric_timeout": 90,
    "max_retries": 2,
    "checkpoint_enabled": True,
    "checkpoint_flush_each_item": True,
    "output_dir": "qym_results/nightly",
    # platform_url / platform_api_key fall back to QYM_BASE_URL / QYM_API_KEY
    # if omitted; set them explicitly only when overriding the environment.
    "run_metadata": {
        "source": "nightly",
        "prompt_version": os.environ.get("PROMPT_VERSION", ""),
        "dataset_version": os.environ.get("DATASET_VERSION", ""),
    },
}

Multi-model run

Same task, dataset, and metrics across several models. Returns a list of results.

results = Evaluator(
    task=my_task,
    dataset=my_dataset,
    metrics=["exact_match", "fuzzy_match"],
    model=["gpt-4o-mini", "gpt-4.1-mini"],
    config={"run_name": "model-comparison"},
).run(show_tui=False)  # list[EvaluationResult]

Multiple run specs

When task, dataset, metrics, or config differ between runs, drive them with run_parallel. Each entry is a dict or a RunSpec.

from qym import Evaluator

results = Evaluator.run_parallel(
    [
        {
            "name": "baseline",
            "task": baseline_task,
            "dataset": dataset,
            "metrics": ["exact_match"],
            "config": {"run_name": "baseline"},
        },
        {
            "name": "candidate",
            "task": candidate_task,
            "dataset": dataset,
            "metrics": ["exact_match"],
            "config": {"run_name": "candidate"},
        },
    ],
    show_tui=False,
    max_parallel_runs=2,
)

Auto-save defaults differ by entry point. run() defaults auto_save=True; arun() and run_parallel() default auto_save=False. Pass auto_save=True explicitly to the async paths when you want artifacts written.

CLI flag mapping

The CLI is a thin shell over the same config. Most run configuration arrives through qym run create flags; everything else goes through --config (a JSON object merged into EvaluatorConfig).

CLI flagMaps to
--task-file, --task-functionLoads the task callable.
--datasetqym platform dataset name, or a local dataset path.
--dataset-version / --dataset-aliasconfig.dataset_version / config.dataset_alias.
--dataset-fileLocal CSV or JSONL dataset file.
--dataset-csvCsvDataset(path).
--csv-input-colCsvDataset(input_col=...) (default input).
--csv-expected-colCsvDataset(expected_col=...) (default expected_output); empty string disables expected output.
--csv-id-colCsvDataset(id_col=...).
--csv-metadata-colsCsvDataset(metadata_cols=[...]) (comma-separated).
--metricsComma-separated metric names.
--modelEvaluator(model=...); comma-separated values become a multi-model run.
--task-nameconfig.task_name.
--configJSON string merged into EvaluatorConfig.
--platform-urlconfig.platform_url.
--platform-api-keyconfig.platform_api_key.
--resume-from (alias --run-file)config.resume_from.
--git-branch / --git-commitconfig.git_branch / config.git_commit.
--ui-portconfig.ui_port.
--no-uiDisables the local web UI.
--no-progressDisables the progress bar.
--quiet / -qOnly show the final summary.
--runs-configMulti-run YAML/JSON loaded into run specs.
--outputSave single-model results to a JSON file.

Concurrency, timeouts, retries, and checkpoint options have no dedicated flags — set them through --config:

qym run create \
  --task-file eval_task.py \
  --task-function answer_question \
  --dataset-csv datasets/smoke.csv \
  --csv-input-col question \
  --csv-expected-col answer \
  --metrics exact_match \
  --task-name support-rag \
  --model gpt-4o-mini,gpt-4.1-mini \
  --config '{"run_name":"ci-smoke","max_concurrency":4,"timeout":120,"max_retries":1}'

There is no --concurrency or --no-tui flag. Set concurrency via --config, and use --no-ui / --no-progress to quiet output. The --live-mode flag exists but is hidden and deprecated.

Common mistakes

MistakeImpactFix
Cranking max_concurrency high before knowing provider limits.Rate limits, timeouts, noisy retries.Start at 2-5 and scale by evidence.
Hardcoding platform_api_key in source.Leaked credentials in version control.Set QYM_API_KEY and leave the field unset.
Putting secrets in run_metadata.Secrets surface in artifacts and the platform UI.Store only non-sensitive labels.
A typo'd local dataset path passed as a string.Resolves to a platform dataset and raises DatasetNotFoundError when creds are missing.Use a concrete CsvDataset/JsonlDataset object, or fix the path. See Datasets.
Disabling checkpoints on long runs.Any interruption forces a full rerun.Keep checkpoint_enabled=True.
Passing empty-string boolean env vars in Docker.Pydantic validation errors.Use explicit true/false, not "".
Expecting run() to print a summary.It prints nothing by default.Set QYM_SHOW_SUMMARY=1 to opt in.
