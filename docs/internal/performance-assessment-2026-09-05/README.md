qym performance assessment, 5 September 2026. Assessed commit `b1d1d00`.

The platform has the larger scaling problems. Its reads and live updates repeatedly process whole runs or histories, and ingestion blocks the API event loop. The SDK's basic execution overhead is relatively small for slower tasks, but upload shutdown, judge clients, progress callbacks, and memory retention need work.

This assessment combines source review, local synthetic benchmarks, and 56 passing focused tests. Platform benchmarks use isolated in-memory SQLite. SDK network/model calls are mocked; frontend benchmarks execute actual source functions in Node without browser rendering. The numbers demonstrate costs and scaling behavior, not production capacity, PostgreSQL latency, or browser end-to-end performance. Raw results are in [measurements.json](measurements.json), with reproducible scripts in the adjacent `benchmarks` directory.

Recommended improvements, ordered by significance. P1 means the next performance work; P2 follows or can run alongside it. No P0 is assigned because this audit did not establish a production outage. Effort estimates include implementation and validation: S roughly 1–2 engineering days, M 3–7 days, L 1–3 weeks or more.

| Rank | Priority | Area and improvement | Evidence, affected workload, and implementation direction | Effort |
|---|---|---|---|---|
| 1 | P1 | Platform: remove blocking ingestion from the API event loop and bulk database operations | The async handler executes synchronous SQL. A 1,000-span batch issued 2,005 SELECTs, 2,001 INSERTs, and 1,001 savepoint/release pairs. Read the request asynchronously, then process it in a bounded worker with its own DB session, or migrate this path to async DB access. Batch duplicate checks and upserts while retaining event ordering and idempotency. [Handler](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/api/ingest.py#L919). | M–L |
| 2 | P1 | Platform: paginate run detail and load large item/pass bodies on demand | The 71 MiB fixture is fetched before client-side pagination. Return a small header plus a bounded item page; fetch text, attempts and judge explanations when opened. Remove duplicate full-text representations. Apply the same contract to comparison. [Snapshot builder](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/api/runs.py#L2576), [browser fetch](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/_static/dashboard/run.html#L6419). | L |
| 3 | P1 | Platform: update trace summaries incrementally | One changed trace still loads every RunItem, restores all other aggregate buckets, and sanitizes all item metadata. Update affected items and apply numeric deltas to run totals, with bounded reconciliation for corrections and retries. Cost should follow changed traces, not run size. [Refresh](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/api/ingest.py#L550). | M–L |
| 4 | P1 | Platform: implement durable dashboard summaries and bounded history reads | The server scans underlying items for list summaries, while the browser drains every 100-run page despite showing 50 rows. At 10,000 runs that means 100 requests. Read durable summaries, use server pagination/filtering, and refresh changed run IDs by revision. The [existing summary contract](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/docs/DASHBOARD_INCREMENTAL_SUMMARY_CONTRACT.md#L3) remains design-only. [Server](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/api/runs.py#L1771), [browser](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/_static/dashboard/dashboard.js#L6087). | L |
| 5 | P1 | Platform UI: index item rows for Models and Compare | Nested `Array.find` makes matching quadratic in item count. Build one item-ID map per run snapshot and reuse it across metrics, filters and render passes. Preserve existing identity/alignment rules. This is the clearest small browser optimization. [Shared metrics](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/_static/dashboard/metrics.js#L157), [comparison](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/_static/dashboard/compare.html#L7228). | S |
| 6 | P1 | SDK: make upload finalization awaitable and bound queued bytes | `arun` calls blocking close and a synchronous final POST. The upload queue has no size limit, so a slow platform also permits memory growth. Add asynchronous drain/finalization, a byte limit and durable spill or asynchronous backpressure; preserve terminal-event ordering and delivery reporting. [Finalization](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/core/evaluator.py#L1741), [queue](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/platform/client.py#L167). | M |
| 7 | P1 | SDK: reuse and close LLM judge clients | Every built-in judge invocation creates an AsyncOpenAI client. Give each run/event loop an owned, reusable client keyed by connection configuration, and close it during async teardown. Avoid sharing async clients across unrelated loops. [Client creation](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/metrics/judges/base.py#L206). | S–M |
| 8 | P2 | Platform: avoid repeating expensive API-key verification | Every request performs 600,000 PBKDF2 iterations. A bounded successful-verification cache can use a token digest plus the current stored hash as its key, while continuing database revocation and user checks. Keep password verification unchanged. A different API-token hash scheme would require a separate migration design. [Verification](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/auth.py#L100), [KDF](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/security.py#L53). | S–M |
| 9 | P2 | SDK: make progress snapshots constant-cost | Snapshots copy all completed/failed indices just to count them. Read set lengths under the existing lock; optionally throttle callbacks. The isolated callback benchmark grew from 0.014 s at 1,000 items to 5.15 s at 30,000. [Snapshot](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/core/observers.py#L153). | S |
| 10 | P2 | Platform: bound analysis admission and persist job state before scaling workers | With two execution workers and a ten-job retention setting, 250 submissions retained 250 jobs and created 250 heartbeat tasks. Retention only prunes terminal jobs. Limit queued jobs and remove per-job 10 ms request-loop polling. Durable job ownership/status is needed before adding API processes; current registries are process-local. [Submission](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/services/analysis_jobs.py#L142), [heartbeat](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/services/analysis_jobs.py#L192), [deployment](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/docker/entrypoint.sh#L12). | M; L for durable workers |
| 11 | P2 | SDK: coordinate metric concurrency and outstanding timeout work | Three independent 50 ms metrics ran 2.68× faster with per-item metric concurrency 3 instead of 1. Add a shared provider/run budget before raising defaults. A separate timeout probe returned while two copies of a synchronous metric still ran; retain accounting for these calls and avoid overlapping retries. [Per-item semaphore](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/core/evaluator.py#L2385), [thread dispatch](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/core/evaluator.py#L2500). | M |

Platform downloads also materialize full datasets. Add iterators/prefetch, optional checkpoint-backed results and streaming exports. This is a source-confirmed memory risk; no production ceiling was measured. [Dataset loading](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/core/dataset.py#L300), [remote pages](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/core/dataset.py#L446), [export](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/api/datasets.py#L2187). | L |

For immediate return, implement ranks 5, 7 and 9 while the platform work in ranks 1–4 is designed. Rank 8 is another small improvement, provided revocation behavior stays correct. Ranking expresses significance; these smaller tasks need not wait for the larger ones.

Additional work, after the main bottlenecks:

- Dispose route listeners during SPA navigation. Scripts are re-executed, but dashboard teardown clears timers without removing all document listeners. Old route state can remain reachable. This is a source finding, not a measured heap leak. [Listeners](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/_static/dashboard/dashboard.js#L6811), [teardown](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/_static/dashboard/dashboard.js#L7117).
- Make unchanged/hidden-tab refreshes cheap. The measured dashboard pipeline took 89 ms at 10,000 summaries and 500 ms at 50,000, before DOM or storage writes. Revision checks and incremental updates belong with rank 4. [Refresh application](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/_static/dashboard/dashboard.js#L6048).
- Verify production asset compression. Referenced dashboard/run HTML, JS and CSS total 0.84/1.24 MB uncompressed; a local gzip comparison reduced these about 80%. The repository app does not configure compression, but the production proxy may already supply it. [Application setup](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/platform/qym_platform/app.py#L27).
- Batch checkpoint writes outside the asyncio loop. Local 5,000-item timing was 0.500 s disabled versus 0.559 s enabled. Slow disks and per-row fsync are the larger concern. [Writer](https://github.com/faisalx96/qym/blob/b1d1d00587df4fcf0e70875c29b0bb0cbc20172c/packages/sdk/qym/core/checkpoint.py#L190).
- Validate composite-index candidates with PostgreSQL `EXPLAIN ANALYZE`, and define raw event/span retention. Neither an index change nor a retention policy should be selected from SQLite timings alone.

Existing strengths should be preserved: bounded SDK item workers, debounced TUI updates, count/byte-limited upload batches, retry backoff, checkpoint resume, cached trace aggregates, event identity constraints, limited concurrent page fetches, and virtualized repeat heatmaps. The old SDK local UIServer is no longer on the evaluator path and is excluded from the primary findings.

Acceptance checks for the first changes:

- Large ingestion batches leave an independent event-loop heartbeat responsive. SQL operations are batched while duplicate and out-of-order fixtures converge correctly. FastAPI's [concurrency documentation](https://fastapi.tiangolo.com/async/#path-operation-functions) explains the distinction between normal handlers run in a thread pool and blocking calls made directly inside async handlers.
- Increasing a run from 1,000 to 100,000 items does not increase the number of item bodies returned in the initial page. Repeat and comparison views obey the same bound.
- Refreshing one trace touches only affected items and bounded summary state. Corrections, retries and late spans preserve exact totals.
- Comparison lookup and callback-only benchmark time grow approximately linearly with item count. Verify optimized outputs against existing results.
- A mocked slow platform keeps queue bytes bounded and sibling async tasks responsive through shutdown. All accepted events are either confirmed delivered or retained durably for retry.
- Judge client creation follows run/configuration lifetime, and owned clients close on success, cancellation and error. HTTPX recommends [reusing async clients for connection pooling](https://www.python-httpx.org/async/#opening-and-closing-clients).

Validation and reproduction notes:

The 56 passing tests cover `test_overhead_breakdown`, `test_parallel_metrics`, `test_observers`, `test_platform_client`, `test_analysis_jobs`, `test_run_detail_payload`, and `test_trace_stats_ingest`. They passed in 38.28 s with 16 dependency/deprecation warnings. This was a focused run, not the full suite. The local Python environment's native `readline` import crashed pytest at startup; setting `sys.modules['readline'] = None` before `pytest.main` bypassed that unrelated import. Missing web dependencies were installed under `/tmp/qym-perf-audit-deps`, leaving the repository environment unchanged.

Benchmark scripts are assessment artifacts, not CI thresholds. Run Python scripts from an empty temporary working directory with the SDK and platform source directories on `PYTHONPATH`, using the versions recorded in `measurements.json`. Clear `QYM_API_KEY`, `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY`, and use `QYM_DATABASE_URL=sqlite:///:memory:`. This prevents loading the repository's `.env`. The platform list script imports the adjacent platform fixture script. Run the frontend benchmark with `node bench_frontend.cjs /path/to/qym`. The overhead wrapper reads the repository benchmark and adjusts its stale assertion in memory; it does not edit that file.

No application code was changed. Added files contain only this assessment, measurements and reproduction scripts.
