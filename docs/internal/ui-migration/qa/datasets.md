# QA: Datasets, Reviews, Trash feature inventory and mapping

Area: `/projects/{slug}/datasets[/..]`, `/projects/{slug}/reviews`, `/reviews`, `/trash`. Old: vanilla `_static/dashboard/{datasets,reviews,trash}.html` at 7814183 (legacy worktree, port 8826). New: `frontend/src/features/{datasets,reviews,trash}` on `ui/qa` (built app, port 8836). Written 2026-10-12 by the datasets/reviews/trash QA agent. Nothing was fixed; this file only records findings.

## Summary

Total rows **131**: OK **86**, CHANGED **26**, BUGGY **9**, MISSING **10**.

The port is close to the old behaviour on every data path I compared: catalog filtering, item sort keys and paging (same first rows for every header, both directions), CSV/TSV/JSON/JSONL/Windows-1256 imports, version aliases, compare numbers, lineage counts, trash paging and search, and the correction queue counters. The docked editor pane, bulk delete, Revert, URL-backed filters, archived banner and web-worker parsing are real improvements (a 60k-row, 11 MB CSV parses in 0.3 s with no main-thread stall; the old page blocked for the whole parse). The defects are mostly in the Reviews All tab and bulk path, the catalog's empty-project header, wizard hand-off navigation, and a handful of dropped details (reasoning badge, hover popover, encoding note, breadcrumb name).

## Method

- Seeded one SQLite DB through the API (`seed.py` in my scratchpad, same shapes as `frontend/e2e/datasets/support.ts`): project `qa` with `big-set` (5,200 items, v1 production with 2 runs of 400/300 items, v2 published with edits/add/delete, v3 draft with two revisions on one item), `small-set`, `private-set` (private), `empty-ds`, an Arabic-named dataset, a deleted dataset, 60 corrections (8 approved, 6 rejected), 70 deleted runs; project `qa2` (3 deleted runs, 3 corrections, later archived through `POST /v1/admin/projects/{id}/archive`); project `emptyp` (no data). Copied the DB for the old server and drove both UIs with Playwright (Chromium 1440x900, plus 800 px).
- Wizard inputs (scratchpad `files/`): UTF-8 BOM CSV, Windows-1256 Arabic CSV, `;`-delimited CSV, TSV, JSON array (with an unknown key), JSONL (20 and 2,500 rows), a malformed JSONL (non-object lines, broken JSON), empty CSV, header-only CSV, a binary blob, and a 60,000-row 11 MB CSV.
- Old behaviours come from the brief (07 sections 2 and 3), the vanilla sources and the running old pages. Each row was verified in the new app unless the notes say "code only" or "not verifiable".
- Spec column names the area spec file(s) under `frontend/e2e/{datasets,reviews,trash}` that exercise that surface (file-level mapping; I did not map each row to a single test title).
- CUTOVER.md gaps in this area (Reviews All-tab focus/advance, "Approve 0" dialog, review history not refetched after approve, 0 ms latency items, trash Restore column sticky, dataset metric without direction) are rows R022, R042, R043, I010, T024, I009 and were each re-checked.

## Not verifiable here

- Non-admin behaviour (private test set locked state, Set-as-production disabled tooltip, Restore/Delete permission gating, `review_block` tooltips and disabled decisions): `QYM_AUTH_MODE=none` makes the only user an ADMIN, and corrections have `corrected_by=null`, so no block is ever produced. Rows are marked "code only".
- Source filter (`ai_only`, `human_only`, `corrected`): `GET /api/corrections?source=..` returns 500 on SQLite for all three values, in old and new (Postgres-only `btrim`, logged in decisions OPEN_QUESTIONS). Only the URL chip is verified.
- Purge countdown warning/danger states (< 3 days, under 1 day, Due now): need deleted runs older than the grace window and the DB must not be hand-edited; only the "in 30 days" and "Paused" states were seen. `purgeInfo` (TrashPage.tsx:18-25) was read.
- Trace drawer button on the item Runs tab: the seeded runs have no traces, so the button renders a dash in the new UI.
- Reviews `Reviewed by .. "comment"` footer: the server returns `reviewed_by: null` under auth none, so it never renders.
