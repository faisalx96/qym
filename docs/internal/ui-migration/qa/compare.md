# QA: Compare page feature inventory and mapping

Area: Compare (`/compare`, `/projects/{slug}/compare`). Old: vanilla `_static/dashboard/compare.html` at 7814183 (legacy worktree, port 8823). New: `frontend/src/features/compare` on `ui/qa` (built app, port 8833). Written 2026-10-12 by the compare QA agent. Nothing was fixed; this file only records findings.

## Summary

Total rows **116**: OK **61**, CHANGED **37**, BUGGY **12**, MISSING **6**.

The ported page is in good shape on the data paths: every statistic I compared (stats strip, winner bar, distribution, categories, error buckets, cohort and Sweep numbers, CSV rows) equals the old page, and the paired band and p-value match scipy (t distribution). Gaps are mostly on presentation: no run summary cards, collapsed rows lose the numeric score, no trace-stat rows, per-pass baseline, a thin HTML export, plus a handful of small defects listed in the Fix list.

## Method

- Seeded one SQLite DB through the API (`frontend/scripts/seed-compare.ts`: 4 aligned runs, a 3-pass repeat run, a short run; plus a traced run, a hand-built 8-item statistics pair `qa-stats` with a maximize and a minimize metric, and a `qa-misc` pair with Arabic text, JSON input/output, list metadata, a 60-line expected answer, a 0 ms item and formula-looking cells), copied it for the old server, and drove both UIs with Playwright (Chromium, 1440x1000, plus 900 and 600 px). Langfuse env vars were set on both servers to exercise the links.
- Old behaviours come from the migration brief (05 sections 2 and 3), the vanilla sources and the running old page; every row was then checked on the new page unless the notes say otherwise.
- CUTOVER.md gaps in this area (Errors tab grouping, Sweep delta tint, analytics tab reset on run removal, missing run ids unnamed, Langfuse CTAs, 0 ms latency items) are rows below and were each re-checked, not taken on faith.

## Paired statistics check (scipy)

Hand-built pair in `qa-stats` (two runs, 8 items, metric `acc` maximize and `err` minimize). Reference from `.venv` scipy 1.x:

| metric | mean base to cand | delta | 95% half-width (t, df 7) | half-width (normal) | p (paired t) | improved / regressed |
|---|---|---|---|---|---|---|
| acc | 51.9 to 61.6 | +9.75 pts | **7.02** | 5.82 | **0.0134** | 6 / 2 |
| err (lower is better) | 31.9 to 24.4 | -7.50 pts | **6.70** | 5.56 | **0.0331** | 6 / 1 |

New page (Metrics tab, tooltip on the delta tag): `acc: +9.8 pts ... (95% noise band +/-7.0, p=0.013)` and `err: -7.5 pts ... (95% noise band +/-6.7, p=0.033)`, counts up 6 / down 2 and 6 / 1, both tinted "improved" (direction-aware). Old page printed +/-5.8 and +/-5.6, i.e. the normal approximation. So the new numbers equal scipy; the old ones are the narrower normal bands. The cohort/Sweep noise model is intentionally still the normal approximation (mirrors `qym.core.reducers.noise_report`); its numbers are identical in both UIs.
